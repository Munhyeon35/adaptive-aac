# 평가와 모델 개선

## 재현 가능한 개발 평가

`python3 -m scripts.evaluate`는 16개 합성 시나리오를 같은 어휘집으로 평가합니다. 매 단계의 목표 그림이 첫 추천 6개에 있으면 1동작, 없으면 전체 그림 열기 1동작과 고정 목록의 페이지 이동·선택 동작을 계산합니다. 고정 그림판은 그림을 고를 때마다 첫 페이지로 돌아갑니다. UI의 전체 목록은 스크롤 방식이므로 여기서 페이지 이동은 탐색 비용을 근사하는 가정입니다.

출력 지표는 다음과 같습니다.

- Top-6 hit rate: 정답 다음 그림이 첫 6개 추천에 들어간 비율.
- 평균 동작 수: 그림 선택 + 가정한 페이지 탐색/전체 목록 열기.
- 감소율: `(1 - adaptive/static) × 100`. 추천이 빗나가면 음수가 될 수 있습니다.
- 시나리오별 원시 동작 수: 평균에 가려진 실패 사례를 확인할 수 있습니다.

현재 평가 스크립트는 로컬 규칙 엔진을 대상으로 합니다. 합성 데이터는 개발 중 추천 설계에도 참조되었으므로 독립된 검증 세트가 아니며, LLM이나 실제 사용자의 효과를 평가한 결과로 사용하면 안 됩니다.

## 실제 사용 기록

앱은 명시적으로 확정한 메시지에 대해 다음을 저장합니다.

- 선택 그림 순서, 최종 문장, 모드, 사용자가 지정한 상황.
- 첫 탐색/선택부터 확정까지 걸린 시간.
- 그림 선택, 취소, 분류 변경, 상황 변경, 추천 새로고침, 전체 어휘 열기의 합계.

문장 편집 키 입력, 스크롤, 문장 생성/확정 버튼, 음성 재생은 선택 동작 합계에서 제외합니다. 앱의 실제 기록과 시뮬레이션 지표는 정의가 다릅니다. UI에 보이는 모드별 평균은 서로 다른 문장의 관측 요약이며 인과 비교가 아닙니다. 미완료/포기 메시지는 저장하지 않으므로 완료율 계산에도 사용할 수 없습니다.

## 참가자 평가 설계

1. 참여자와 보호자의 동의 및 프로젝트의 연구 절차를 먼저 정합니다.
2. 식사, 음료, 장소, 물건, 불편함을 포함한 동일 의도 과제를 준비합니다. 자발적인 다른 의도도 허용합니다.
3. 고정/규칙 추천/LLM 추천 조건의 순서를 교차 배치하고, 같은 그림과 화면 크기를 사용합니다.
4. 사용자의 그림 해석 여부를 확인하고, 도움 제공 여부를 기록합니다.
5. 선택 동작, 시간, 추천 적중, 수정/재추천, 전체 어휘 사용, 완료/포기를 기록합니다. 현재 앱에서 기록하지 않는 항목은 관찰 기록으로 보완합니다.
6. 오류가 있는 문장이 사용자 의도와 어떻게 달랐는지 사람이 검토합니다. 단순 선택 횟수 감소만으로 성공을 판정하지 않습니다.
7. 참가자/과제별 결과와 표본 크기를 보고합니다. 사용자의 표현권과 부담에 대한 피드백을 함께 다룹니다.

## 파인튜닝 단계

1. 설정의 JSON 내보내기에서 승인된 데이터를 확보합니다. 자동 수집한 실제 사용자 자료는 저장소에 넣지 않습니다.
2. 선택 실수와 직접 수정한 문장을 검토합니다. 자동 예제 생성기는 최종 문장과 그림의 의미 일치를 검증하지 않습니다.
3. `scripts.prepare_training`으로 접두 선택→다음 그림 예제를 생성합니다. 현재 생성기는 개인 이름과 자유 문장을 사용하지 않습니다.
4. **예제 확장 전** 참가자/세션/과제 묶음 단위로 학습/검증/최종 평가 데이터를 분리합니다. 동일 문장의 여러 접두사가 양쪽에 섞이면 데이터 누출이 생깁니다. 현재 내보내기는 프로필 ID를 제거하므로 참가자 구분은 동의된 별도 메타데이터나 파일 단위로 관리해야 합니다.
5. 사용할 모델/플랫폼의 학습 형식과 지원 모델을 확인하고 실제 학습 작업을 실행합니다. 비용이 발생하는 업로드·학습은 자동화하지 않았습니다.
6. 고정된 평가 세트로 기존 프롬프트 모델과 학습 모델을 비교합니다. Top-k, 어휘 외 출력, 부정 의도 보존, 개인화 전/후, p50/p95 지연, 실패 시 fallback 비율을 보고합니다.
7. Responses API 호환 학습 모델을 선택했다면 `OPENAI_MODEL`을 바꾸어 연결할 수 있습니다. 다른 형식의 모델은 `aac/llm.py` 인터페이스에 맞는 어댑터가 필요합니다.

현재 제공하는 JSONL은 학습 입력을 준비하는 도구이며 학습된 모델 체크포인트가 아닙니다.
