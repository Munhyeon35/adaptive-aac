# 평가와 모델 개선

## 브라우저 비전 LLM 사용자 평가

Python 3.11+, Node 20+, Chrome 또는 Chromium, 로그인된 Codex CLI가 필요합니다. Python 환경에는 `requirements-dev.txt`를 설치합니다. 평가 실행 시 지정된 모델에 임시 브라우저의 합성 과제 화면과 연구 요약을 보냅니다. 실제 프로필과 사용 기록은 읽지 않습니다.

```bash
PYTHON=.venv/bin/python CHROMIUM_PATH=/absolute/path/to/chrome node scripts/evaluate-agent.mjs --persona direct_touch_motor --task food_request --output artifacts/agent-evaluation.json
```

필터 없이 `make evaluate-agent`를 실행하면 두 사용자 유형과 일곱 의도를 기본 그림판과 맞춤 추천에서 비교합니다. `--mode`, `--max-turns`, `--model`, `--screenshots`로 단일 모드, 행동 한도, 모델, 관찰 화면 저장을 지정할 수 있습니다. 평가가 길어질 수 있으며 `--output`은 매 시도가 끝날 때마다 갱신됩니다. `PYTHON`과 `AAC_CODEX`로 실행 파일을 지정할 수 있습니다.

`--local-manifest var/active-model.json`과 해당 모델의 `PYTHON`을 추가하면 맞춤 추천에 설치된 로컬 Qwen을 사용합니다. `board_sources`에서 적용된 추천 엔진을 확인할 수 있습니다. 비전 LLM은 어느 조건에서도 사용자 행동과 자기 평가를 맡습니다.

### 사용자 행동과 연구 근거

`data/agent-scenarios.json`의 가상 사용자는 연구에 공개된 관찰 결과를 프롬프트로 받습니다. 같은 모델이 현재 Chrome 화면의 이미지와 화면에 보이는 버튼 번호를 보고 누르기, 스크롤, 대기, 중단 중 하나를 직접 고릅니다. 브라우저는 그 결과를 적용하고 새 화면을 보여 줍니다. 사용자가 표현하려는 의도는 자연어로 주어지며, 정답 카드나 정해진 선택 순서는 제공하지 않습니다.

- **직접 터치 운동 접근 프로필**은 버튼 크기와 간격을 고려해 선택, 오선택 또는 복구를 결정합니다. 이상운동형 뇌성마비 아동 10명의 실험은 목표 선택, 인접 선택, 빗나간 터치와 반응·이동 시간을 관찰했습니다. 실제 가정 내 AAC 관찰에서 보인 대화 상대의 도움은 단독 사용 평가의 범위 밖입니다. [터치 실험](https://pmc.ncbi.nlm.nih.gov/articles/PMC6101246/), [가정 내 iPad AAC 관찰](https://doi.org/10.1177/0265659013518338)
- **직접 터치 시각 탐색 프로필**은 밀집한 카드와 눈에 띄는 분류 단서를 고려합니다. 다운증후군 청소년·성인 10명의 시선 추적 실험에서 카드 배열에 따라 무관한 그림을 주시한 횟수가 달라졌습니다. [시각 탐색 실험](https://pmc.ncbi.nlm.nih.gov/articles/PMC9132148/)

연구의 집단 관찰을 가상 프로필에 반영했습니다. 개별 이용자를 재현하거나 임상적 사용성을 검증하려면 실제 참여자 데이터가 필요합니다.

### 지표와 채점

- `viewport_card_exposures`는 앱이 화면에 절반 이상 들어왔거나 선택된 카드로 센 횟수입니다. `model_reported_unique_cards`는 모델이 스스로 확인했다고 보고한 카드의 수이고, 시선 추적 데이터는 수집하지 않습니다.
- `completion_ms`는 시작 화면부터 전달이 확인될 때까지의 실측 시간입니다. `decision_ms`는 모델 호출 시간, `elapsed_without_model_ms`는 호출 시간을 뺀 브라우저·실행기 시간입니다. 미완료는 `completion_ms`가 비어 있고 `attempt_ms`가 남습니다.
- 비전 LLM이 동일한 사용자 역할에서 앱이 실제로 전달한 문장과 의도를 비교합니다. 5점은 완전 전달, 4점은 핵심 전달, 3점은 부분 전달, 2점은 불일치, 1점은 미전달입니다. 점수에는 시간이나 카드 수를 반영하지 않습니다.

## 6장 고정 가정 평가

`python3 -m scripts.evaluate`는 16개 합성 시나리오를 같은 어휘집으로 평가합니다. 매 단계의 목표 그림이 첫 추천 6개에 있으면 1동작, 없으면 전체 그림 열기 1동작과 고정 목록의 페이지 이동·선택 동작을 계산합니다. 고정 그림판은 그림을 고를 때마다 첫 페이지로 돌아갑니다. 여기서 6장 단위 페이지 이동은 실제 화면의 탐색 비용을 근사하는 가정입니다.

출력 지표는 다음과 같습니다.

- Top-6 hit rate: 정답 다음 그림이 첫 6개 추천에 들어간 비율.
- 평균 동작 수: 그림 선택 + 가정한 페이지 탐색/전체 목록 열기.
- 감소율: `(1 - adaptive/static) × 100`. 추천이 빗나가면 음수가 될 수 있습니다.
- 시나리오별 원시 동작 수: 평균에 가려진 실패 사례를 확인할 수 있습니다.

이 스크립트는 기존 6장 가정을 유지하는 규칙 엔진 평가입니다. 브라우저 사용자 에이전트 평가는 브라우저의 카드 노출과 화면에서 수행한 행동을 측정합니다. 합성 데이터는 개발 중 추천 설계에도 참조되었으므로 독립된 검증 세트가 아니며, LLM이나 실제 사용자의 효과를 평가한 결과로 사용하면 안 됩니다.

## 실제 사용 기록

앱은 명시적으로 확정한 메시지에 대해 다음을 저장합니다.

- 선택 그림 순서, 최종 문장, 모드, 사용자가 지정한 상황.
- 첫 탐색/선택부터 확정까지 걸린 시간.
- 화면에 절반 이상 들어왔거나 선택한 카드 수. 같은 그림판이나 전체 어휘 페이지를 스크롤하거나 다시 렌더링할 때는 중복을 빼고, 다른 화면을 표시하거나 전체 목록을 다시 열면 새로 셉니다. 비활성 탭과 대화상자 뒤에 가려진 그림판은 제외합니다. 이전 기록에는 카드 노출 값이 없고, 평균은 측정값이 있는 메시지로 계산합니다.
- 그림 선택, 취소, 분류 변경, 상황 변경, 추천 새로고침, 전체 어휘 열기의 합계.

문장 편집 키 입력, 스크롤, 문장 생성/확정 버튼, 음성 재생은 선택 동작 합계에서 제외합니다. 앱의 실제 기록과 시뮬레이션 지표는 정의가 다릅니다. UI에 보이는 모드별 평균은 서로 다른 문장의 관측 요약이며 인과 비교가 아닙니다. 미완료/포기 메시지는 저장하지 않으므로 완료율 계산에도 사용할 수 없습니다.

## 참가자 평가 설계

1. 참여자와 보호자의 동의 및 프로젝트의 연구 절차를 먼저 정합니다.
2. 식사, 음료, 장소, 물건, 불편함을 포함한 동일 의도 과제를 준비합니다. 자발적인 다른 의도도 허용합니다.
3. 고정/규칙 추천/LLM 추천 조건의 순서를 교차 배치하고, 같은 그림과 화면 크기를 사용합니다.
4. 사용자의 그림 해석 여부를 확인하고, 도움 제공 여부를 기록합니다.
5. 선택 동작, 시간, 추천 적중, 수정/재추천, 전체 어휘 사용, 완료/포기를 기록합니다. 현재 앱에서 기록하지 않는 항목은 관찰 기록으로 보완합니다.
6. 오류가 있는 문장이 사용자 의도와 어떻게 달랐는지 사람이 검토합니다. 단순 선택 횟수 감소만으로 성공을 판정하지 않습니다.
7. 참가자/과제별 결과와 표본 크기를 보고합니다. 사용자의 표현권과 부담에 대한 피드백을 함께 다룹니다.

## 파인튜닝 단계

1. 설정의 JSON 내보내기에서 승인된 데이터를 확보합니다. 자동 수집한 실제 사용자 자료는 저장소에 넣지 않습니다.
2. 선택 실수와 직접 수정한 문장을 검토합니다. 자동 예제 생성기는 최종 문장과 그림의 의미 일치를 검증하지 않습니다.
3. `scripts.prepare_training`으로 접두 선택→다음 그림 예제를 생성합니다. 현재 생성기는 개인 이름과 자유 문장을 사용하지 않습니다.
4. **예제 확장 전** 참가자/세션/과제 묶음 단위로 학습/검증/최종 평가 데이터를 분리합니다. 동일 문장의 여러 접두사가 양쪽에 섞이면 데이터 누출이 생깁니다. 현재 내보내기는 프로필 ID를 제거하므로 참가자 구분은 동의된 별도 메타데이터나 파일 단위로 관리해야 합니다.
5. 사용할 모델/플랫폼의 학습 형식과 지원 모델을 확인하고 실제 학습 작업을 실행합니다. 비용이 발생하는 업로드·학습은 자동화하지 않았습니다.
6. 고정된 평가 세트로 기존 프롬프트 모델과 학습 모델을 비교합니다. Top-k, 어휘 외 출력, 부정 의도 보존, 개인화 전/후, p50/p95 지연, 실패 시 fallback 비율을 보고합니다.
7. Responses API 호환 학습 모델을 선택했다면 `OPENAI_MODEL`을 바꾸어 연결할 수 있습니다. 다른 형식의 모델은 `aac/llm.py` 인터페이스에 맞는 어댑터가 필요합니다.

로컬 모델 다운로드·QLoRA 학습·전후 비교·앱 연결은 `setup_local.py`로 실행할 수 있습니다. 자세한 실행 조건과 합성 데이터 분리 방식은 [로컬 모델 안내](local-model.md)를 확인하세요. JSONL 데이터 생성만 성공한 상태와 실제 어댑터 학습이 성공한 상태는 각 실행의 상태 파일로 구분합니다.
